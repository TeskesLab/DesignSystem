Start with the observation

A useful note tells the next reader what happened, under which conditions, and where the evidence lives. Keep the observation separate from the explanation you are testing.

For this sample, the capture contains a repeating burst. The note records the receiver settings and a timestamp, while the original recording remains attached as a source.

Evidence is available. Interpretation is provisional.

A linked source establishes provenance. Review status is a separate field.

Keep the evidence close

Use a concise summary for orientation, then let readers inspect the exact passage or artifact when they need it.

Leave a useful next step

State what remains uncertain and what would resolve it. Preserve the previous note when new evidence changes the conclusion.

Implementation contract

Build it once. Keep it consistent.

Use named tokens and verified behavior. Each product keeps the layout its work needs.

One source of values

Edit tokens/source.json, then regenerate exports. Components consume semantic roles such as text-link and control-border.

Brand Coral remains an editorial accent. Error states use dedicated foreground/background pairs.

Three layout patterns

Reading: comfortable prose and contextual evidence. Workspace: resizable regions and explicit operations. Monitoring: current state, timestamps, and drill-down.

Only the first two have interactive reference screens in this release.

Accessible by construction

  • Keyboard focus stays visible and returns after dialogs.
  • Labels and icons explain status without depending on color.
  • Web touch controls target 44 px; Android targets 48 dp.
  • Test zoom, large text, long names, and reduced motion.

Platform implementations

Web has working CSS and JavaScript examples. Qt, Fyne, and Android have mappings and integration specifications.

Native behavior must be checked in the actual toolkit and application. The HTML reference is a visual and interaction baseline.

What a component must include

Purpose, anatomy, variants, tokens, states, keyboard behavior, accessible name, responsive behavior, and test cases.

Implement success, failure, loading, empty, unknown, and permission states wherever they apply.

Before adopting a release

Pin a version. Review the migration notes and reference images. Run the supplied token checks and browser tests, then validate inside the target product.

Document justified exceptions with an owner, reason, and review condition.
